# G6：G5 + OCC 预测头缩减及近场网格

配置 `bevdet-b0-det-occ-g6-occ128-nearfield.py` 继承 G5 official-fast。

- 共享图像网络、LSS（±51.2 米、0.8 米、59 档深度）、BEV 编码器、检测分支保持 G5 设置。
- OCC adapter 直接采样为 128×128，XY 范围 [-25.6,25.6)，间隔 0.4 米。
- OCC 预测头 128→128→288，Softplus；最终语义输出 128×128×16，18 类。
- 标签和两类 mask 在翻转增强后，从原 200×200 中裁剪 [36:164,36:164]。验证/测试评估同步裁剪 GT，仅评估该近场范围；mIoU 不能直接与 G5 全范围 mIoU 比较。
- 从 G5 FP epoch_20_ema.pth 初始化；尺寸变化的 predicter.0.weight、predicter.0.bias、predicter.2.weight 重新初始化。加载时这三项 size mismatch 属预期，其他不匹配须检查。
- 继承 G5 fast 的四卡设置：每卡16、workers8、AMP、AdamW lr5e-5、20 epoch、EMA；这是 FP 微调配置，不是 QAT 配置。
- 独立输出目录 work_dirs/ep1_g6_occ128_nearfield。

无验证训练命令：

```bash
conda activate bevdet
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
bash tools/dist_train.sh configs/bevdet/ep1_bevdet+flashocc/bevdet-b0-det-occ-g6-occ128-nearfield.py 4
```

检查记录 work_dirs/g6_config_check/：真实训练样本及 collate、CPU OCC forward、裁剪评估、G5 原预测头默认宽度不变，G5 检测参数正常加载。未运行完整 GPU 训练或板端测速。
部署时后处理必须使用新的 OCC 输出尺寸和原点（-25.6 米），不可沿用 G5 的200×200/−40米设置。
